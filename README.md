# Supplier OTD Scorecard

An explainable, dependency-free supplier delivery scorecard for procurement and operations teams. Give it a purchase-order CSV and it produces a supplier-level on-time delivery (OTD) summary, delay distribution metrics, and a Markdown report.

## Business question

Which suppliers are consistently missing their promised dates, and is there enough delivery history to make that comparison useful?

The tool counts a completed order as on time when `delivered_at <= promised_at`. Orders without a delivery date are reported as open and excluded from delivery-rate denominators. A supplier is marked `watch` only if it has at least 20 deliveries and its OTD is more than 10 percentage points below the portfolio rate. These explicit rules help prevent open-order censoring and tiny samples from distorting a simple scorecard.

## Quick start

Requires Python 3.10+ and no third-party packages.

```bash
python supplier_otd.py demo --output demo-output
python -m unittest -v
```

The deterministic demo writes `purchase_orders.csv`, `scorecard.json`, `supplier_metrics.csv`, and `report.md`. To score your own file:

```bash
python supplier_otd.py score path/to/purchase_orders.csv --output report
python supplier_otd.py score path/to/purchase_orders.csv --output report --min-deliveries 30 --watch-gap 0.15
```

## Input contract

UTF-8 CSV (a UTF-8 BOM is accepted) with these required columns:

| Column | Meaning |
|---|---|
| `order_id` | Unique purchase-order identifier |
| `supplier` | Supplier label |
| `ordered_at` | Order date, ISO `YYYY-MM-DD` |
| `promised_at` | Promised delivery date, ISO `YYYY-MM-DD` |
| `delivered_at` | Actual delivery date, ISO `YYYY-MM-DD`; blank while still open |

Malformed dates, duplicate order IDs, missing identifiers, promised dates before order dates, and delivery dates before order dates fail with a row-specific error. The scorecard uses the data as supplied; it does not infer contractual calendars, split partial deliveries, or adjust for order value.

## Metrics and interpretation

- **OTD**: share of delivered orders arriving on or before the promised date.
- **Mean, median, and P90 delay**: days between actual and promised dates; early deliveries are negative, and an on-time delivery has zero delay. P90 uses the nearest-rank definition.
- **`watch`**: a triage flag relative to the whole delivered-order portfolio, after the minimum-sample rule. It is not a statistical significance test or a supplier quality verdict.
- **`insufficient`**: fewer than the configured minimum number of delivered orders.

## Reproducible demo results

The fixed-seed demo generated 330 fictional purchase orders across six fictional suppliers. Of these, 324 were delivered and six were still open. The overall OTD among completed orders was **86.1%**. With the default 20-delivery minimum and 10-point gap, Cobalt Components (70.4%) and Eastern Freight (72.2%) were flagged `watch`; the other four suppliers were `ok`. These are generated example results, not observed supplier performance.

## Design and limitations

The implementation uses Python's standard library so it can run offline and is easy to audit. It calculates transparent descriptive statistics rather than fitting a predictive model. Comparisons are unadjusted: differences in product mix, lanes, order size, seasonality, and promised lead-time policy can make supplier rates incomparable. Open orders may be systematically different from completed ones, so the OTD rate is a completed-order metric, not a forecast of ultimate performance. Use the watch flag to prioritize investigation, not to automate sourcing decisions.

## Data provenance

All demonstration records are synthetic and generated by `supplier_otd.py` with a fixed random seed. No external or private data is included.
